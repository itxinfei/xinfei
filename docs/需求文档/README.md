# 需求文档集（入口）— 给大模型的阅读指引

> 本目录是**心飞外卖系统面向大模型（AI）全栈开发的需求文档集**，共七份文档。任何 AI 开发会话**从这里开始**：按你要做的事查下表的「必读组合」，读完再动代码。

## 文档地图

| 文档 | 回答的问题 | 什么时候读 |

| [产品修复计划.md](./产品修复计划.md) | 产品评审产出的分级修复路线（P0 生死线/P1 增强/P2 硬化） |

## 按任务类型的必读组合

| 任务 | 必读（按顺序） |
|---|---|
| 任何开发会话开工 | ① 约束.md ② `AGENTS.md`（仓库根，唯一事实来源总纲） |
| 后端功能开发 | 约束.md → Java设计.md → `docs/模块与接口.md`（查可复用模块）→ `docs/架构设计.md` |
| 后台页面开发 | 约束.md → UI设计.md → `docs/Element-Plus迁移计划.md` → `page/_templates/list-page.html` 骨架 |
| 小程序开发 | 约束.md → UI设计.md（§5）→ `miniapp/README.md`（页面台账与接口契约） |
| 接需求 / 排期 | 功能升级.md → PRD.md（业务域归属）→ 功能调研.md（对标依据） |
| 数据库结构变更 | 约束.md（§2.2 落地路径）→ `docs/FLYWAY_MIGRATION.md` |

## 使用规则（给大模型）

1. **冲突裁决**：本目录任何文档与 `AGENTS.md` 冲突，以 `AGENTS.md` 为准，并回改本目录文档。
2. **完成回写**：做完一项待办 → 在 [功能升级.md](./功能升级.md) 对应 O-xx 标 ✅ 与日期（验收标准怎么验的要写清）；新发现的缺口按「可查证」标准登记新条目（注明来源 文件:行号 或 文档§节）。
3. **不做未决策项**：标「待确认/待评估」的条目在用户决策前不得开工；「明确不做」清单见 PRD.md §5.3，改变口径先改文档再排期。
4. **文档同步**：改动落地后同步 `CHANGELOG.md` 与受影响文档；文档与代码不一致时以代码实测为准并回改文档。
