## 1. 产品概述

### 1.1 产品定位

**心飞外卖（xinfei_takeout）** 是一个面向餐饮门店的**多租户 SaaS 外卖管理系统**，覆盖从商家端（管理后台）到消费者端（C 端）的完整业务闭环：

- **商家侧**：员工登录 → 菜品/套餐/分类维护 → 接单 → 收银/日结 → 财务对账 → 报表分析；
- **消费者侧**：用户登录 → 选品 → 购物车 → 下单 → 支付 → 收货/堂食；
- **平台侧**：与第三方平台（美团/饿了么）双向同步菜品、库存、订单与对账；
- **运营侧**：库存/成本/营销/会员/留存/推荐/客服/多店联动/企业餐补。

支持三种业态：

| 业态 | 标识 | 说明 |
|---|---|---|
| 外卖 | `TAKEOUT` | 传统外卖配送，含骑手、配送时效、地址簿 |
| 堂食 | `EAT_IN` | 桌台、桌区、开台结账、二维码点餐 |
| 排队/预约 | `QUEUE` / `RESERVATION` | 排队叫号、预约到店 |

### 1.2 市场背景与差异化定位（提炼自竞品分析）

- 餐饮数字化市场 2026 年突破千亿元、年复合增长 20%+；餐饮 SaaS 2025 年约 320 亿元；连锁化率升至 25%；餐饮 AI 渗透率仅约 15%，处于早期窗口。
- 头部厂商（美团收银、客如云、哗啦啦、有赞/微盟、思迅等）普遍以云 SaaS + 硬件 + 年费/抽佣模式经营；外卖平台抽佣 20–25% 倒逼品牌做私域。
- 本产品的差异化在于：**开源可自建、零许可费、代码透明可深度二开、经营数据自主可控**，直接对应三类市场痛点：①连锁品牌「数据自主可控、不绑定平台」诉求；②信创/私有化部署刚需；③SaaS 年费与平台抽佣下的降本诉求。
- 竞品分析报告同时指出本项目相对市场主流的系统性差距（云原生化、开放生态、硬件抽象层、等保/信创合规等），详见该报告 §4 与 [功能调研.md](./功能调研.md)；其中多项已在后续迭代中补齐（多租户、会员体系、AI、平台对接、小程序端），见 §5 完成状态。

### 1.3 目标用户与核心价值

| 用户 | 核心诉求 | 本产品提供的价值 |
|---|---|---|
| 门店店长/收银员 | 快速接单、收款、日结 | 收银台 + 订单流转 + 一键日结 + 工作台待办 |
| 连锁/多店管理者 | 多店管控、经营对比 | 多租户 + 总部—门店看板（`parent_tenant_id` 聚合） |
| 顾客 | 便捷点餐、支付、售后 | H5 + 微信小程序点餐、微信 JSAPI 支付、客服/发票/评价 |
| 骑手 | 接单配送、结算提现 | 骑手端接单/轨迹上报/收入结算/提现 |
| 企业客户（B 端） | 员工餐补 | 企业餐补账户与发放 |

**小程序门店端（staff）——明确只迁移动高频场景**：看单—接单—完成、门店状态（营业/暂停接单）、工作台概览、员工登录/我的。**后台其余约 77 页（表单/图表密集型维护功能）不做小程序**，继续走 Web 后台。

**小程序顾客端**：点餐主链路 + 订单/售后 + 会员/优惠券/充值 + 收藏/足迹/消息 + 发票（含 PDF 查看）+ 排队/预订 + 客服（含图片消息/凭证图）+ AI 助手 + 配送跟踪 + 评价图片上传。明确不迁/暂缓：扫码点餐（依赖桌台码入口，暂缓）、原 H5 收银台/支付成功页（已由统一支付闭环取代）、SSE 实时消息（改下拉刷新）、AI 流式对话（改非流式）。

**小程序骑手端**：接单大厅/任务流转/收入/评价/异常工单/消息/结算提现 + 在途单 12s 位置自动上报。Web 骑手端 8 页功能已全覆盖。

**明确不做/不属于本产品范围**：官网落地页不迁小程序；后台不做完整小程序版（见上）；支付宝小程序内无 JSAPI 能力，支付入口保持灰显（后端支付宝渠道仅 NATIVE/PC/WAP）。

## 4. 非功能需求

> 从架构文档提炼，数字仅引用文档中可查证者，不编造。

### 4.1 鉴权与会话

- 三类主体会话：员工（Session+Cookie，HttpOnly、SameSite=strict）、骑手、顾客；非 JWT。
- 接口鉴权注解：`@RequiresAdmin`（仅超管）、`@RequiresPermission`、`@RequireEmployee`（员工会话）；混合公开/顾客端点的 Controller 只能方法级标注。
- **双通道会话**：2026-10-22 起支持 Token 通道（`X-Auth-Token`，Redis 存储，TTL 默认 72h 可配），供小程序使用；Web/H5 的 Session 通道零改动共存，Redis 降级时回落 401。
- 顾客短信验证码迁 Redis（TTL 5 分钟、一次性消费），HttpSession 作降级回落；频控三层：Redis 冷却 60s（跨会话）→ Redis 快计数 → DB 台账（`sms_send_log`）权威兜底。

### 4.2 租户隔离与数据安全

- MyBatis-Plus 租户插件自动注入 `tenant_id`；`permission`、`role_permission` 两表无 tenant_id，走专用 Mapper。
- 生产敏感配置 Jasypt `ENC(...)` 加密 + 环境变量注入；密码 BCrypt；日志脱敏。
- CSRF：Web 端 CSRF Token 契约保存/回传；dev 真实禁用、生产启用。HTTP 安全头（CSP/nosniff/HSTS 等）过滤器。
- 接口限流（Redis Lua）注解化；分页统一封顶（`PageUtils.cap` 上限 100）。
- openid 不回传前端；上传/下载接口已同时认 Session 与 `X-Auth-Token` 登录态（2026-10-24 起，小程序图片与发票 PDF 已接通）。

### 4.3 可用性与运行

- 生产 Redis 必须开启持久化（AOF 或足够频繁 RDB）：短信防盗刷与限流计数键依赖 Redis，重启静默清空会使冷却防线失效（开发机实测发生过）。
- 短信/推送 dev 默认 mock-mode 不真发；支付有 mock 沙箱（`payment.mock-mode=true`）可无证书走完整链路。
- 生产 Flyway 默认不自动执行 DDL（`FLYWAY_ENABLED:false` 红线）。
- 结构变更一律走 Flyway 迁移，已入库脚本禁止改动。
- 自动化测试：1064+ 用例（2026-10-24 新增 5 个测试类后约 1085）/ 136 可执行测试类，JDK 25 + Boot 4.1.1 下历史全绿；另有 `tests/` E2E 套件（Playwright）与 `miniapp/packages/shared` node:test 9 例。

### 4.4 性能与并发

- dev/prod 开启虚拟线程（覆盖 Tomcat 请求线程与 Boot taskScheduler；自建线程池仍为平台线程并承担背压限流）。
- 技术栈口径：Spring Boot 4.1.1 / JDK 25 / MySQL / Redis（详见 AGENTS.md，需求侧仅约束「多租户单库 + Redis 缓存」架构不变）。
- 高并发指标未在输入文档中给出量化承诺——**待确认**（如需量化，先补压测数据再写死，禁止拍脑袋）。
