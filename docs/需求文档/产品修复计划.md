## P0 生死线（留存/转化否决项，建议立即排期）

### P0-1 顾客端订单状态推送（微信订阅消息）— M
- **现状（实测）**：全仓 `requestSubscribeMessage` 零调用；顾客感知订单进度的唯一方式是打开小程序轮询（消息中心下拉刷新 / 详情页 15s 轮询）。
- **痛点**：点外卖的核心等待焦虑（接单了吗/骑手取餐了吗）无任何主动触达，体验落后美团一个时代；这是顾客留存的否决项。
- **方案**：①后端新增 `WechatSubscribeMessageService`（复用 `WxCode2SessionClient` 的 appid/secret 换 access_token，模板 ID 走 `xinfei.wechat-miniapp.subscribe.*` 配置）；②下单成功页/订单详情请求订阅（一次性订阅规则：接单提醒 + 送达提醒两个模板）；③订单状态机三个关键节点触发推送——商家接单（status 2）、骑手取餐（pickup）、订单送达/完成（status 4）；④失败静默不阻塞主流程（与既有通知模块同口径）。
- **涉及**：后端 notification 模块 + order 状态机挂点；小程序 checkout/detail 页。
- **验收**：真机下单 → 后台接单 → 微信收到服务通知；订阅额度用尽时降级无报错。

### P0-2 老板驾驶舱（小程序）— S
- **现状**：门店端 6 页全是店员操作视角；老板「晚上看一眼今天」的场景在手机上无承载，Web 报表不适用手机。
- **痛点**：SaaS 续费决策人是老板，不是店员；触达不了老板的产品留不住账。
- **方案**：staff 小程序新增 `pages/boss/boss` 一页：今日营业额/订单数/客单价（复用 `GET /api/dashboard/overview`）+ 库存预警 Top5（复用 warning 接口）+ 待处理退款数 + 交班台账摘要；全部现成接口零后端改动。
- **涉及**：仅 staff 小程序。
- **验收**：老板登录 staff 端首页即见核心指标，离线数据有刷新时间标注。

### P0-3 新商户引导向导 — M
- **现状**：系统光彩建立在租户 1 演示数据上；新租户进来面对 82 页后台 + 写得很好的空态，无任何引导。
- **痛点**：time-to-first-order 决定商户激活率，这条路现在是「自己摸索」。
- **方案**：后台首登检测（无菜品/未配置营业时间 → 弹出向导）：①建店信息+营业时间 → ②建分类 → ③传首个菜品 → ④（可选）打印桌码 → ⑤上线营业。每步完成打勾，可跳过，全部完成后不再出现。进度存 localStorage。
- **涉及**：后台 Web（新增向导组件 + index.html 首登检测）；零后端改动。
- **验收**：新租户首登被引导走完五步并成功下单第一单；跳过后可从工作台重新进入。

## P1 体验增强（上线后第二个迭代）

### P1-1 骑手端新单提醒（前台声震）— S
- **现状（实测）**：骑手端 vibrate/innerAudio 零调用；抢单大厅靠人眼刷新。
- **痛点**：骑手在路面场景，新单出现无感知 = 抢单慢 = 收入体验差。
- **方案**：大厅页轮询 diff 到新任务时 `uni.vibrateLong()` + innerAudioContext 短提示音 + tabBar 角标；**诚实边界**：小程序后台不运行，提醒仅前台有效——真后台推送依赖 P0-1 的订阅消息体系扩展骑手模板（登记为 P1-1b，依赖 P0-1）。
- **验收**：前台停留大厅页，新单投放时手机震动+提示音。

### P1-2 顾客端菜品搜索 — S
- **现状（实测）**：点餐首页（index.vue）无搜索入口；菜单长时找菜全靠滑动。
- **方案**：首页顶部分类区上方加搜索框：本地按当前菜品名/描述过滤（数据已全量在手）+ 跳转结果面板；后端 `/dish/list` 已有 name 参数可作兜底。搜索历史 3 条存 storage。
- **验收**：搜索「饭」即时过滤出含关键字菜品；清空恢复全量。

### P1-3 券到期主动提醒 — S
- **现状（实测）**：coupon 页仅静态「已过期」标签，无临期感知。
- **方案**：「我的券」列表内 `3 天内到期` 的券加「即将过期」角标并置顶排序；领取成功 Toast 附有效期文案。（推送级提醒依赖 P0-1，不重复计）
- **验收**：构造临期券，列表首位+角标可见。

### P1-4 AI 助手流式体验 — L（暂缓，依赖 uni.request SSE 不可用的现实）
- **现状**：小程序 AI 走非流式，长回答等待感明显。
- **方案（暂缓理由）**：uni.request 无法消费 POST+SSE（README 已载）；可行替代是 enableChunked 分块响应改造后端，属专项。保持登记不动。
