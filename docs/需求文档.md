## 1. 产品概述

### 1.1 产品定位

**心飞外卖（xinfei_take_out）** 是一个面向餐饮门店的**多租户 SaaS 外卖管理系统**，覆盖从商家端（管理后台）到消费者端（C 端）的完整业务闭环：

- **商家侧**：员工登录 → 菜品/套餐/分类维护 → 接单 → 收银/日结 → 财务对账 → 报表分析；
- **消费者侧**：用户登录 → 选品 → 购物车 → 下单 → 支付 → 收货/堂食；
- **平台侧**：与第三方平台（美团/饿了么）双向同步菜品、库存、订单与对账；
- **运营侧**：库存/成本/营销/会员/留存/推荐/客服/多店联动/企业餐补。

支持三种业态：

| 业态 | 标识 | 说明 |
|---|---|---|
| 外卖 | `TAKEOUT` | 传统外卖配送，含骑手、配送时效、地址簿 |
| 堂食 | `EAT_IN` | 桌台、桌区、开台结账、二维码点餐 |
| 排队/预约 | `QUEUE` / `RESERVATION` | 排队叫号、预约到店 |

### 1.2 市场背景与差异化定位（提炼自竞品分析）

- 餐饮数字化市场 2026 年突破千亿元、年复合增长 20%+；餐饮 SaaS 2025 年约 320 亿元；连锁化率升至 25%；餐饮 AI 渗透率仅约 15%，处于早期窗口。
- 头部厂商（美团收银、客如云、哗啦啦、有赞/微盟、思迅等）普遍以云 SaaS + 硬件 + 年费/抽佣模式经营；外卖平台抽佣 20–25% 倒逼品牌做私域。
- 本产品的差异化在于：**开源可自建、零许可费、代码透明可深度二开、经营数据自主可控**，直接对应三类市场痛点：①连锁品牌「数据自主可控、不绑定平台」诉求；②信创/私有化部署刚需；③SaaS 年费与平台抽佣下的降本诉求。
- 竞品分析报告同时指出本项目相对市场主流的系统性差距（云原生化、开放生态、硬件抽象层、等保/信创合规等），详见该报告 §4 与 [需求文档/功能调研.md](./需求文档/功能调研.md)；其中多项已在后续迭代中补齐（多租户、会员体系、AI、平台对接、小程序端），见第 7 章完成状态。

### 1.3 目标用户与核心价值

| 用户 | 核心诉求 | 本产品提供的价值 |
|---|---|---|
| 门店店长/收银员 | 快速接单、收款、日结 | 收银台 + 订单流转 + 一键日结 + 工作台待办 |
| 连锁/多店管理者 | 多店管控、经营对比 | 多租户 + 总部—门店看板（`parent_tenant_id` 聚合） |
| 顾客 | 便捷点餐、支付、售后 | H5 + 微信小程序点餐、微信 JSAPI 支付、客服/发票/评价 |
| 骑手 | 接单配送、结算提现 | 骑手端接单/轨迹上报/收入结算/提现 |
| 企业客户（B 端） | 员工餐补 | 企业餐补账户与发放 |

## 2. 技术栈与工程约束（摘要）

> 本章是给 AI 开发助手的**约束摘要 + 指向**，逐条细节以 `AGENTS.md` 与各专篇文档为唯一事实来源，不要以本章替代阅读原文。设计动机见 [需求文档/Java设计.md](./需求文档/Java设计.md) 与 [需求文档/UI设计.md](./需求文档/UI设计.md)。

### 2.1 后端栈（JDK 25 / Spring Boot 4.1.1）

| 层 | 约束 |
|---|---|
| 语言/构建 | JDK 25（本机 `D:\Program Files\Java\jdk-25.0.3`，PATH 上 java 是 JDK 21，构建前必须 export JAVA_HOME）；Maven 无 wrapper；允许 `var`/`record`/`List.of()`/text block/sealed/ScopedValue；**必须 `jakarta.*`**（`javax.crypto`/`javax.sql` 等 JDK 自带包除外） |
| 框架 | Spring Boot 4.1.1 / Spring 7.0.9；Boot 4 模块化拆分——`spring-boot-starter-aspectj`（原 aop 改名）、`spring-boot-flyway` + `flyway-mysql`（缺了迁移静默不执行）、`spring-boot-webmvc-test`、`spring-boot-http-client` + `spring-boot-restclient`（test）等需显式引 |
| ORM | MyBatis-Plus 3.5.17，必须 `mybatis-plus-spring-boot4-starter`；租户插件需 `mybatis-plus-jsqlparser`；Mapper 逐接口 `@Mapper` 注册（**无 @MapperScan**）；Mapper XML 放 `src/main/resources/com/xinfei/<包路径>/` |
| 连接池/迁移/缓存 | HikariCP（**Druid 已移除且禁止切回**）；Flyway 12.4.0（已入库脚本禁止改动，新变更从下一版本号起）；Redis + Commons Pool2 |
| 序列化 | **Jackson 3**（`tools.jackson.*`）全量迁移完成，业务代码禁引 `com.fasterxml.jackson.databind`；自定义 `@Primary` bean 返回类型必须写 `JsonMapper`（写 ObjectMapper 会双 primary 启动失败）；`JacksonException` 已是 unchecked，catch 链注意裸抛 |
| 分层 | 41 个模块 `com.xinfei.module.<module>`（controller/mapper/model/service）+ `common/`/`config/`/`dto/`/`enums/`/`filter/`/`utils/`；统一响应 `com.xinfei.common.R<T>` |
| 租户与分页 | MP 租户插件自动注入 `tenant_id`；`permission`/`role_permission` 无 tenant_id 已入 `IGNORE_TABLES`（查这两表须走专用 Mapper）；分页必须 `PageUtils.of/cap`（上限 100），禁裸 `new Page<>` |
| 配置键 | `spring.redis.*` 已迁 `spring.data.redis.*`；`@ConditionalOnProperty`/`@Value` 引用需核对 |

### 2.2 前端与小程序栈

| 端 | 约束 |
|---|---|
| 管理后台 `src/main/resources/backend/` | Vue 3 + Element Plus，原生 JS **无编译**（改完硬刷新即生效）；新页面照 `page/_templates/list-page.html` 与 `docs/Element-Plus迁移计划.md` 骨架写 |
| 顾客/骑手端 `front/`、`rider/` | Vue 3 + Vant 4，原生 JS 无编译 |

| 设计令牌 | 颜色一律引 `styles/tokens.css`，**禁硬编码 hex**；合规例外仅三类（canvas 走 `window.XinfeiPalette`、CSS/HTML `var(--token, #hex)` 回退值），勿当违规「修复」 |
| crud-table 对齐 | 唯一来源 `components-v3.js` 的 `resolveColAlign`：全站表头与内容一律居中，禁页面零散写 `align`、禁翻转默认值 |
| 小程序 `miniapp/` | pnpm workspace + uni-app（Vue 3 + Vite），**Options API、纯 JS，禁 `<script setup>`/TypeScript**；产物不入库、不由 Spring Boot 伺服；`@RequestParam` 语义的 POST/PUT 必须用 `qs()` 拼进 URL（uni.request 无 axios params）；令牌真源在 Web 侧，改后跑 `pnpm sync:tokens` |

### 2.3 关键工程纪律（易踩坑，细节指向 AGENTS.md）

- 构建前 `export JAVA_HOME="D:/Program Files/Java/jdk-25.0.3"`。
- 测试连真实 MySQL（单库 `xinfei`）+ Redis；开发/测试靠租户隔离（演示=租户 1、测试=租户 999），**禁止整表 DELETE**；新增表/列须同步 `src/test/resources/schema*.sql`，显式主键 insert 前用 `TestIdGuard.assertAbsent`。
- Redis 生产必须开持久化（限流/短信冷却键依赖）；短信/推送 dev 默认 mock。
- Spring 7 禁 `addResourceLocations("classpath:/")`，引导页由默认 `classpath:/static/` 承载。
- 虚拟线程开关只覆盖 Tomcat 与 Boot taskScheduler，自建线程池仍平台线程（背压限流中）。
- Mapper XML、配置文件 git 跟踪口径等见 AGENTS.md「文件与 Git 注意」。

### 3.2 新需求落地路径

| 场景 | 路径 |
|---|---|
| 新增表/列 | ① 写 `db/migration/V<n>__描述.sql`（dev 启动自动执行，编号顺延、避开已占用段）；② 同步测试夹具（基础表进 `src/test/resources/schema.sql`，模块表进 `schema-<module>.sql`，照抄 `SHOW CREATE TABLE`，行内/表级 PRIMARY KEY 不能共存）；③ 演示种子若用固定主键，避开测试硬编码主键段与演示数据占用段 |
| 新增后台页面 | 照 `page/_templates/list-page.html` 骨架 + Element-Plus 迁移计划契约；API 封装进 `api/<module>.js`；挂载侧边栏 `index.html` |
| 新增后端模块 | 进对应 `com.xinfei.module.<module>`（controller/mapper/model/service）；复杂 Mapper XML 放与 Java 包同路径的 resources 目录 |
| 新增小程序页面 | 按台账逐页补，接口路径/字段名照 Controller 原样（不改名），`@RequestParam` 语义用 `qs()` 拼 URL |
| 结构/行为变更 | 一律 Flyway 新版本纠正，**已入库脚本禁止改动**（checksum 变更会使已迁移库启动失败） |

### 3.3 红线清单（禁止事项）

- **禁止**重新引入 Vue 2 / Element UI 资产（含从 git 历史），后台/顾客/骑手端禁止降回旧组件库或同页混用两套组件库。
- **禁止**改动已入库的 Flyway 迁移脚本；**禁止**对生产库自动执行 DDL（prod `FLYWAY_ENABLED:false` 红线）。
- **禁止**整表 `DELETE`（测试清理只按租户 999/命名空间条件删，未登记全局表 fail-fast）。
- **禁止**切回 Druid；**禁止**裸 `new Page<>` 或不封顶透传 pageSize；**禁止**类级 `@RequireEmployee` 加在混合公开端点的 Controller 上。
- **禁止**硬编码 hex（除三类合规例外）；**禁止**单独给表头写死对齐、翻转列对齐默认值。
- **禁止**显式映射 `classpath:/`；**禁止**手写 `new ObjectMapper()` 等 Jackson 2 写法回退。
- 小程序**禁止** `<script setup>` / TypeScript / 手改令牌同步产物。
- 前端修改后未浏览器硬刷新实测不得视为完成。

### 3.4 开发流程纪律（全栈大模型开发工作方式）

> 技术红线见 3.3；本节约束**做事的流程**，适用于任何人机协作开发会话。

**开工前：先读文档，再动代码**

1. 改任何后端代码前读 `AGENTS.md` 对应章节；改后台页面前读 `docs/Element-Plus迁移计划.md`；改小程序前读 `miniapp/README.md`；改表结构前读 `docs/FLYWAY_MIGRATION.md`。
2. 拿到需求先判断归属：新功能 → 先查 `docs/模块与接口.md` 是否已有可复用模块/端点，**禁止重复造轮子**；找不到再新增，且新代码进对应 `com.xinfei.module.<module>`。
3. 涉及表结构 / 测试夹具 / 演示数据三者必须同步改（Flyway 迁移 + `schema*.sql` + 核对 `db/xinfei.sql` 演示 ID 段占用），漏一步就是测试炸或撞主键。

**开发中：小步提交，单一职责**

1. **一个任务一次改动**：一次会话只做一件事（一个功能/一个修复），禁止「顺手」重构无关代码、顺手升级依赖、顺手统一三端组件库。发现别的问题 → 记进本文 §8 待办清单，不当场扩散。
2. **改动前先看现场**：改文件前必须先读它；推翻或覆盖别人（含以往会话）写的代码前，先核对与文档口径是否矛盾，矛盾时停下来向用户说明，不自行裁决。
3. **遵循现状，不做美学重构**：代码风格跟随周围代码；「看起来可以更好」不构成改动理由。项目无 lint/format 门禁，一致性靠自觉。
4. 除 3.3 红线外，历史踩坑浓缩的典型禁手：把 `ObjectMapper` 写回 `@Primary` bean 返回类型（双 primary 启动失败）；恢复 `admin-spa/` 工程；测试里显式主键 insert 前不跑 `TestIdGuard.assertAbsent`。

**完成后：必须验证，诚实汇报**

1. **编译验证铁律**（来自 `.codebuddy/memory/MEMORY.md`）：Java 改动必须 `export JAVA_HOME="D:/Program Files/Java/jdk-25.0.3"` 后跑 `mvn compile`（或 `mvn test -Dtest=相关类`）验证通过才算完成；「我认为能编译」不算。
2. 涉及数据库的改动，本地跑相关测试类确认（测试连真实 MySQL/Redis，需先启动二者）。
3. **测试失败必须如实报告**：贴失败输出，说明原因与修复方案；禁止掩盖、跳过（`@Disabled`）或删除断言来「让测试变绿」。
4. 汇报格式：做了什么 / 改了哪些文件 / 怎么验证的 / 遗留什么。没验证的说「未验证」，没做完的说「没做完」，禁止夸大完成度。
5. 改动落地后同步文档：`CHANGELOG.md`、受影响的专项文档、以及本文 §7/§8。文档与代码不一致时以代码实测为准并回改文档。

## 6. 非功能需求

> 从架构文档提炼，数字仅引用文档中可查证者，不编造。

### 6.1 鉴权与会话

- 三类主体会话：员工（Session+Cookie，HttpOnly、SameSite=strict）、骑手、顾客；非 JWT。
- 接口鉴权注解：`@RequiresAdmin`（仅超管）、`@RequiresPermission`、`@RequireEmployee`（员工会话）；混合公开/顾客端点的 Controller 只能方法级标注。
- **双通道会话**：2026-10-22 起支持 Token 通道（`X-Auth-Token`，Redis 存储，TTL 默认 72h 可配），供小程序使用；Web/H5 的 Session 通道零改动共存，Redis 降级时回落 401。
- 顾客短信验证码迁 Redis（TTL 5 分钟、一次性消费），HttpSession 作降级回落；频控三层：Redis 冷却 60s（跨会话）→ Redis 快计数 → DB 台账（`sms_send_log`）权威兜底。

### 6.2 租户隔离与数据安全

- MyBatis-Plus 租户插件自动注入 `tenant_id`；`permission`、`role_permission` 两表无 tenant_id，走专用 Mapper。
- 生产敏感配置 Jasypt `ENC(...)` 加密 + 环境变量注入；密码 BCrypt；日志脱敏。
- CSRF：Web 端 CSRF Token 契约保存/回传；dev 真实禁用、生产启用。HTTP 安全头（CSP/nosniff/HSTS 等）过滤器。
- 接口限流（Redis Lua）注解化；分页统一封顶（`PageUtils.cap` 上限 100）。
- openid 不回传前端；上传/下载接口已同时认 Session 与 `X-Auth-Token` 登录态（2026-10-24 起，小程序图片与发票 PDF 已接通）。

### 6.3 可用性与运行

- 生产 Redis 必须开启持久化（AOF 或足够频繁 RDB）：短信防盗刷与限流计数键依赖 Redis，重启静默清空会使冷却防线失效（开发机实测发生过）。
- 短信/推送 dev 默认 mock-mode 不真发；支付有 mock 沙箱（`payment.mock-mode=true`）可无证书走完整链路。
- 生产 Flyway 默认不自动执行 DDL（`FLYWAY_ENABLED:false` 红线）。
- 结构变更一律走 Flyway 迁移，已入库脚本禁止改动。
- 自动化测试：1064 用例 / 131 可执行测试类，2026-10-20 在 JDK 25 + Boot 4.1.1 下 100% 通过；另有 `tests/` E2E 套件（Playwright）。

### 6.4 性能与并发

- dev/prod 开启虚拟线程（覆盖 Tomcat 请求线程与 Boot taskScheduler；自建线程池仍为平台线程并承担背压限流）。
- 技术栈口径：Spring Boot 4.1.1 / JDK 25 / MySQL / Redis（详见 AGENTS.md，需求侧仅约束「多租户单库 + Redis 缓存」架构不变）。
- 高并发指标未在输入文档中给出量化承诺——**待确认**（如需量化，先补压测数据再写死，禁止拍脑袋）。
